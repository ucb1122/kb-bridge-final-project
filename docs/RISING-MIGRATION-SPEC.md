# 최종 프로젝트 이식 명세: 디자인·동작·수치

> 이 문서를 `kb-bridge-final-project`에 복사해 최종 작업의 기준으로 사용한다. 근거는 사용자가 대화에서 제공한 서울시 공식 화면 캡처, 테스트 프로젝트의 실제 구현, `docs/RISING-AREA-DEVELOPMENT-NOTES.md`다. 테스트 화면은 참고 구현이며 공식 서비스 전체를 완전히 복제한 것은 아니다. 공식 캡처와 테스트 구현이 다르면 캡처에서 확인되는 요구사항을 우선한다.

## 1. 지금 바로잡을 방향

현재 최종 저장소는 테스트 앱을 그대로 이식한 결과가 아니다. Python/Streamlit으로 화면을 다시 조립하고 테스트 DB와 일부 공식 스냅샷을 읽도록 만들었다. 그래서 **화면 배치, 상세조건, 보고서 카드, 지도 동작이 달라졌고**, 지표에 따라 목록·지도·보고서에 서로 다른 출처의 값이 나타날 수 있다.

새 기능을 추가하기 전에 다음을 완료한다.

1. 뜨는 상권의 화면과 선택 동작을 이 문서의 계약에 맞춘다.
2. 같은 지역·분기·업종·지표가 목록/지도/보고서/PDF에서 같은 정의와 출처를 사용하도록 고친다.
3. 사용자 캡처의 사례를 실제 데이터로 대조한다. 공식값을 모르는 지역을 임의 보정하지 않는다.

## 2. 유지할 프로젝트 결정

- 최종 기술은 **Python + Streamlit + SQLite**, 지도는 `.env.example`의 **카카오 JavaScript 지도 키**다. 테스트 프로젝트가 Node/HTML/JS라고 해서 기술 스택을 독단적으로 바꾸지 않는다.
- 상위 메뉴는 `뜨는 상권`, `내상권 분석`, `젠트리피케이션 경고`다. `내상권 분석`에는 기존 `나는 사장`과 `나도 곧 사장`을 두 모드로 합친다. 경고는 검증 전까지 `개발 예정`.
- 로그인, 실제 상담 접수/예약, 실제 은행 심사, 사업자 자동조회는 구현된 것처럼 표시하지 않는다.
- 최종 저장소의 `AGENTS.md`, `docs/COLLABORATION.md`, 이슈/브랜치/커밋/PR 규칙을 먼저 따른다. README는 해당 작업 범위에 포함될 때만 고친다.
- 테스트 앱의 화면 구조와 기능 기준 파일: `pages/rising/index.html`, `styles.css`, `map-enhancements.css`, `main.js`, `report-view.js`, `full-report.js`. 최종 앱의 관련 파일: `app_pages/rising.py`, `kb_bridge/ui/rising_layout.py`, `kb_bridge/ui/kakao_rank_map.py`, `kb_bridge/repositories/rising_snapshot.py`, `kb_bridge/services/rising_analysis.py`.

## 3. 뜨는 상권 화면 계약

### 3.1 전체 배치

데스크톱은 **상단 헤더 + 전체 지도 + 지도 위 왼쪽 조건/순위 패널 + 지역 선택 시 오른쪽 보고서 패널**이다. 지도는 화면의 중심 콘텐츠다. 하단에 불필요한 흰 여백이 생기지 않아야 한다. 왼쪽과 오른쪽 패널 내부가 각각 스크롤된다.

```text
┌────────────────────────────────────────────────────────────────┐
│ 서비스 헤더 / 뜨는 상권 / 내상권 분석 / 경고(개발 예정)         │
├─────────────┬────────────────────────────────┬─────────────────┤
│ 자치구      │ 지도 상단 지역 선택창          │ 분석 리포트     │
│ 지역 유형   │                                │ 지역·순위·PDF   │
│ 4개 지표    │   순위 번호·지역명·값 배지     │ 보고서 탭 5개   │
│ 상세조건    │   실제 행정동/상권 경계        │ 종합의견       │
│ TOP 10      │                                │ 지표 카드 3개   │
└─────────────┴────────────────────────────────┴─────────────────┘
```

참고 구현의 데스크톱 폭은 왼쪽 `clamp(300px,22vw,360px)`, 오른쪽 `clamp(460px,35vw,650px)` 수준이다. 정확한 픽셀보다 **지도 공간이 보이고 패널이 잘리지 않는 것**이 우선이다. 왼쪽과 오른쪽은 각각 접기/펼치기가 가능하다. 오른쪽 **닫기**는 선택 지역을 해제하지만 **접기**는 선택을 유지한다. 좁은 화면은 세로 또는 바텀시트로 재배치한다.

### 3.2 왼쪽 패널의 순서

1. `뜨는 상권` 제목, 자치구 선택, 필요 시 행정동 선택/지도 전체 표시.
2. `뜨는 동네` / `뜨는 상권` 2분할 토글. 전자는 행정동, 후자는 상권 코드다. 두 공간 범위를 섞지 않는다.
3. `점포수 / 매출 / 유동인구 / 거주인구` **가로 4칸** 버튼. 선택 항목은 서울시 계열 파란색, 나머지는 밝은 회색/흰색. 아이콘과 이름을 칸 안에 정렬한다.
4. `상세조건` 접이식 영역.
5. 별도 `순위 TOP 10` 영역. 범위, 지표, 기준분기, 출처를 표시하고 각 행에 번호·지역명·값·증감률/증감액을 정렬한다. 상위 3위 번호는 노란색 계열이다.

지도 위에도 `서울특별시 / 자치구 / 행정동 / 접기` 선택창이 있어야 한다. 왼쪽 자치구와 지도 위 자치구는 같은 적용 상태로 동기화한다. 지도 위 행정동으로 **TOP 10 밖 지역도 선택**할 수 있다. 그 지역에 임의 순위를 붙이지 않는다.

### 3.3 상세조건

기본은 **비교증가율 / 보유한 최신 분기 / 전분기 / 전체 업종**이다. 선택 중인 임시 상태와 실제 적용 상태를 분리한다.

| 그룹 | 선택값 | 계약 |
| --- | --- | --- |
| 기준조건 | 최고순위, 비교증가율, 비교절대값 | 각각 현재값, 비교 시점 대비 증가율, 증감 절대값으로 정렬 |
| 기간 | 분기, 년도 | 기준분기/기준년도 버튼 전환 |
| 기준분기 | 보유한 최근 분기 | 원본이 없는 분기 선택 금지 |
| 조회분기 | 전분기, 동분기 | 후자는 전년 같은 분기와 비교 |
| 기준년도 | 보유 연도 | 보유하지 않은 2023·2024년을 사용 가능하게 표시하지 않음 |
| 업종 | 전체, 외식업, 서비스업, 소매업 | **가로 4칸, 글자 오른쪽 SVG 계열 아이콘**, 각각 all/CS1/CS2/CS3 |
| 하단 | 취소, 적용 | 취소는 적용 상태 복원. 적용 후 목록·지도·보고서 갱신 |

업종은 원본 세부 자료가 있는 점포수·매출에만 적용한다. 유동인구·거주인구를 선택하면 업종을 전체로 돌리거나 비활성화한다. 보유 자료가 없는 조합에는 가짜 순위·0을 표시하지 않는다. 기존 테스트 구현에서 연도 집계는 매출·유동인구 같은 유량은 비교 가능한 분기를 합산하고, 점포수·상주인구 같은 상태량은 마지막 분기를 사용한다. 최종 Python에서 이 규칙을 검증한 뒤 적용한다.

### 3.4 카카오 지도

- 목록과 지도 배지는 **같은 순위 배열**로 만든다. 배지에 번호, 지역명, 지표값을 함께 보여준다. 기본 디자인은 보라색 반투명 원/말풍선 계열, 상위 순위는 노란 번호다.
- 반투명 원은 시각 요소이지 실제 반경·면적이 아니다. 실제 경계는 지역 코드가 맞는 GeoJSON 다각형이다.
- 호버 시 경계와 배지를 강조하고 지역명을 보여준다. 클릭 시 보고서를 고정한다. 카카오 오버레이가 경계 이벤트를 가리지 않아야 한다.
- 자치구 선택 시 지도 중심/줌과 순위 범위가 함께 바뀐다. 행정동 선택 시 해당 지역 보고서를 연다.
- 경계 자료와 통계의 행정동 코드 버전이 다르면 다른 지역의 경계를 대신 그리지 않는다. 경계 미확인 상태를 표시한다.
- 키 누락, 허용 도메인 오류, 경계 누락, 지도 로드 오류를 구별해 알린다. 지도가 실패해도 목록·보고서는 이용 가능해야 한다.

### 3.5 오른쪽 보고서

선택 시 오른쪽에 `뜨는 동네/상권`, 자치구·지역명, 선택 지표의 순위·값·변화, PDF 저장, 닫기를 표시한다. 탭 5개는 한 줄의 `종합의견 / 업종분석 / 매출분석 / 인구분석 / 지역(배후지)분석`이다. 탭 변경은 지역과 조건 선택을 지우지 않는다.

**종합의견의 핵심 배열**은 상단 글머리표 요약 아래 **가로 3개 카드**다.

1. 점포수.
2. 매출액 **(점포당 월평균)**.
3. 유동인구 **(3개월간 1ha당 인구수)**. 면적이 없으면 명/ha를 만들지 말고 분기 총량임을 명시한다.

각 카드의 순서는 `전분기 대비 → 현재 분기 값 → 전년 동분기 대비 → 나의 등수(확인된 경우)`다. 증가 **분홍**, 감소 **파랑**, 현재값 **연한 회색**. 부호와 단위를 모든 칸에 적는다. 좁은 화면에서만 카드가 세로로 쌓인다. 현재 최종 앱의 기본 `st.metric` 4개와 이 배열은 다르다. Streamlit으로 구현하되 최종 화면은 이 구조를 따라야 한다.

요약의 지역명·변화·검증 수치에만 파란 강조를 쓴다. AI 생성 중에는 빈 상자를 두지 말고 데이터 기반 요약 또는 상태 문구를 보인다. AI 문장은 검증된 보고서 수치 위에 얹으며 수치 자체의 출처가 아니다.

다른 탭은 테스트 앱 `full-report.js`의 내용 목록과 원본 세부 데이터로 검증한다. 없는 항목은 그럴듯한 그래프를 만들지 말고 `자료 없음`으로 표시한다. PDF/ZIP은 선택한 지역·분기·단위·출처, 한글 폰트, 5개 파일의 내용과 압축 무결성을 확인한다.

### 3.6 시각 언어

뜨는 상권의 기능 색상: 서울시 파랑 `#087dd1` 부근, 보라 배지 `#6433d9` 부근, 상위 번호 노랑 `#ffe500`, 증가 분홍 `#ec4d95`, 감소 파랑 `#278ce0`, 현재값 회색 `#f5f5f5`. 공통 KB 브랜드 헤더를 유지하더라도 **선택/증감 상태의 의미와 카드 배치**는 보존한다. 이모지만으로 모든 아이콘을 대체하지 말고 출처·권리를 확인한 SVG/이미지 자산을 사용한다.

## 4. 수치 계약

모든 표시값은 내부적으로 최소 `kind, region_code, quarter, metric, industry, scope, value, unit, aggregation, source, source_date, verification`을 가진다. 순위 `row.value`만 공식값으로 바꾸고 보고서 `metrics.sales.value`는 원본값으로 유지하는 식의 암묵적 혼합을 금지한다.

| 이름 | 계산/원본 | 화면 단위 | 주의 |
| --- | --- | --- | --- |
| 점포수 | 해당 지역·분기 업종별 전체 점포 수 합계 | 개 | 지역 유형과 업종 범위를 동일하게 |
| 분기 추정매출 합계 | 해당 지역·분기 추정매출 | 원/억 원 | 월평균과 다른 지표 |
| 점포당 월평균 매출 | 분기 매출 합계 ÷ 3개월 ÷ 해당 분기 점포수 | 만 원/점포/월 | 계산값과 공식 보고서 값 구분 |
| 분기 유동인구 총량 | 지역·분기 원본 | 명/만 명 | 밀도와 다른 지표 |
| 3개월간 1ha당 유동인구 | 분기 총량 ÷ (공식 분석면적㎡ ÷ 10,000) | 명/ha | 면적 없으면 계산 금지 |
| 거주/상주인구 | 해당 지역 원본 | 명 | 유동인구와 합산 금지 |

**공식 스냅샷의 적용 범위를 좁게 유지한다.** 확인된 공식 보고서 값은 해당 지역·분기·지표에만 쓴다. 공식 TOP 10 응답은 해당 지역 유형·자치구·분기·지표·기본 상세조건에만 적용한다. 나머지는 `공개 원본 계산값`으로 표시한다. 공식 순위 매출액을 3개월·점포수로 나누면 공식 보고서 월평균과 항상 같다는 가정은 하지 않는다.

최종 코드에서 확인된 불일치 위험:

- `rising_snapshot.rankings()`는 공식 매출 순위의 일부 `row.value`와 `change`를 스냅샷으로 덮지만 `report()`의 `metrics.sales.value`는 원본 observations다. 같은 화면의 순위/지도와 보고서가 다른 출처가 될 수 있다.
- `sales_per_store_month()`는 공식 보고서 값이 없으면 공식 순위값 또는 CSV값을 3개월·점포수로 나눈다. 이는 **계산값**이며 공식 화면 일치가 검증된 값이 아니다.
- `footfall_per_ha()`는 분석 면적 기준 계산값이다. 분기 총량을 같은 이름 `유동인구` 카드에 함께 넣으면 사용자가 서로 다른 값을 오류로 이해한다.
- 비교자료가 없으면 `0`·`0%`·변동 없음으로 표시하지 않는다. `비교 자료 없음`을 쓴다.
- `비교절대값` 선택 시 증감액/수로 정렬하고 같은 단위를 표시한다. 증감률과 혼동하지 않는다.

## 6. 최종 저장소의 구현 순서

1. 현재 브랜치·PR·변경 파일을 기록하고 작업을 보존한다.
2. 원본 ZIP/CSV, 생성 SQLite, 공식 순위/보고서 스냅샷, GeoJSON의 분기·지역 유형·해시·출처를 목록화한다. `data/local` 복사본은 재생성 가능한 최종 적재 파이프라인이 아니다.
3. 순위·지도·보고서·PDF가 쓰는 **하나의 출처 인식 서비스 응답 계약**을 만든다. 다른 지표는 다른 키/단위로 둔다.
4. 위 회귀 사례를 fixture로 만들고 지역 유형·코드·분기·업종·비교조건별 값, 순서, 증감을 검증한다. 데이터 누락으로 건너뛰는 테스트와 필수 통합 테스트를 분리한다.
5. 상단 헤더/지도 높이/좌우 패널/내부 스크롤/접기를 먼저 완성해 하단 흰 여백과 겹침을 해결한다.
6. 상세조건의 임시/적용 상태, 지도 상단 선택, 목록·배지·경계·보고서 동기화를 구현한다.
7. 보고서 5개 탭, 종합의견 3개 카드, PDF 5종과 ZIP을 구현한다.
8. **실제 브라우저**에서 사용자 캡처와 같은 폭으로 화면을 비교한다. 자동 테스트 통과만으로 카카오 오버레이·경계·여백이 해결됐다고 주장하지 않는다.
9. 그 뒤 `내상권 분석`의 운영자/예비 창업자 두 모드, 팀원 디자인·기능을 별도 회귀 목록으로 이식한다. 금융 입력은 지역 통계와 분리한다. 젠트리피케이션은 검증 전까지 예정으로 둔다.

## 7. 완료 기준

- 기본 화면에서 지도, 왼쪽 4개 지표, 상세조건, TOP 10이 한눈에 보이고 선택 시 오른쪽 보고서가 열린다.
- 데스크톱 하단 흰 여백, 잘린 보고서, 겹친 지도 선택창이 없다. 양쪽 패널은 내부 스크롤과 접기가 된다.
- 상세조건 기본값, 업종 4칸의 글자·아이콘 배치, 적용/취소, 전분기/동분기 비교가 맞는다.
- 종합의견은 글머리표 요약과 **가로 3개 카드**를 보인다. 매출 분기 합계/점포당 월평균, 유동인구 총량/ha당 밀도를 정확히 구분한다.
- 같은 선택 조건의 목록·지도·보고서·PDF가 같은 지역·분기·지표·단위·출처를 사용한다.
- 위 회귀 사례의 값과 순서가 실제 DB 테스트로 확인된다. 스킵된 테스트 개수를 보고한다.
- 카카오 지도 배지·경계·지역 선택·패널 접기·PDF를 브라우저에서 확인한다. 미확인 항목은 완료로 표시하지 않는다.

## 10. 권장 데이터·서비스 계약

원본 관측값, 계산값, 공식 확인값을 분리한다.

- source_dataset: 제공기관, 자료명, 파일명, 기준분기, 수집시각, 해시, 이용 조건.
- region: 행정동/상권 유형, 지역 코드, 이름, 자치구, 좌표, 경계 버전.
- observation: 지역·분기·지표·업종, 원본 값과 단위, 원본 파일 참조.
- derived_metric: 점포당 월평균 또는 ha당 밀도, 계산식, 사용한 분모와 관측값 참조.
- verified_display: 공식 화면 또는 순위 응답에서 확인한 값, 적용 조건, 증거와 확인 시점. 원본 observation을 덮어쓰지 않는다.

화면으로 보내는 한 지표에는 최소 지역 유형, 지역 코드, 분기, 지표, 업종, 범위, 값, 단위, 집계 방식, 출처, 확인 여부가 있어야 한다. 값 누락은 null로 전달하고 화면에는 자료 없음으로 표시한다. 확인 여부는 그 지역·분기·지표를 실제 공식 화면과 대조했는지의 뜻이다.

비교값 계산 규칙:

1. 점포당 월평균의 현재·전분기·전년 동분기는 각 분기의 매출과 해당 분기의 점포수로 **각각** 계산한 뒤 차이를 낸다. 현재 점포수를 과거 매출의 분모로 재사용하지 않는다.
2. 유동인구 밀도 비교는 시점별 분석 면적을 확인한다. 면적이 없거나 달라진 여부를 모르면 공식 증감값 또는 비교 자료 없음으로 처리한다.
3. 증가율의 비교 분모가 0·누락이면 0%라고 표시하지 않는다.
4. 중간 계산에서는 반올림하지 않는다. 최종 화면에서만 반올림한다. 반올림한 값끼리 차이를 내면 1만 원·1명 차이가 생긴다.
5. 공식 기본 순위 응답과 공식 보고서 값은 독립된 출처다. 하나를 다른 지표의 대체값으로 쓰지 않는다.

## 11. 반드시 추가할 테스트

### 순수 계산 테스트

- 점포당 월평균 계산과 점포수 0/누락 처리.
- 전분기·전년 동분기의 점포수와 매출을 각각 사용한 증감 계산.
- 유동인구 총량과 면적의 ha당 환산, 면적 0/누락 처리.
- 연도 모드에서 매출·유동인구는 비교 가능한 분기 합산, 점포수·상주인구는 마지막 분기.
- 최고순위/증가율/절대변화 정렬, 동률과 값 누락 처리.

### 저장소·서비스 통합 테스트

- 원본 파일로 임시 SQLite 생성 → 동일 파일 재적재 → 행 수·합계·중복 없음 확인.
- 공식 스냅샷 적용 조건의 지역 유형×지표×분기×자치구×전체 업종×전분기×증가율을 확인. 조건 하나라도 바뀌면 계산값과 출처로 돌아가는지 확인.
- 공식값 있는 지역과 없는 지역의 provenance를 각각 확인.
- 목록 배열, 지도 배지, 선택 보고서의 지역 유형·코드·분기 일치 확인.
- TOP 10 밖 행정동 선택 후 보고서가 열리고 순위는 없음으로 표시되는지 확인.
- 카카오 키 없이도 목록과 보고서가 열리는지 확인.
- PDF/ZIP 파일을 실제로 열어 값·단위·지역명·한글 폰트를 검사.
- 데이터가 없어 스킵된 테스트와 필수 통합 테스트를 분리해 결과에 명시.

### 실제 브라우저 확인

Streamlit AppTest의 위젯 통과만으로 지도와 CSS를 검증할 수 없다. 사용자 스크린샷과 비슷한 화면 폭에서 아래를 실제 브라우저로 확인한다.

1. 헤더, 전체 지도, 좌우 패널이 보이고 하단 흰 여백이 없는지.
2. 지도 리사이즈 뒤 배지와 경계 좌표가 밀리지 않는지.
3. 카카오 지도 인증 성공, 배지, 경계 호버와 선택이 동작하는지.
4. 왼쪽과 지도 위 자치구 선택이 동기화되는지. TOP 10 밖 지역도 열리는지.
5. 상세조건은 수정 중에는 순위를 바꾸지 않고 적용·취소로만 바뀌는지.
6. 종합의견이 글머리표와 가로 3개 카드이며 색상·단위·부호가 맞는지.
7. 보고서 닫기와 접기가 서로 다르게 동작하는지. PDF와 ZIP을 열 수 있는지.

화면 비교 결과는 통과/불일치/미검증으로 적고, 불일치마다 캡처·선택 조건·기대값·실제값을 남긴다.

## 13. 새 창에서 작업 시작 시

이 파일을 최종 저장소로 복사한 뒤 그 저장소의 현재 Git 상태, AGENTS.md, 열린 이슈와 PR, 실제 소스 파일을 다시 확인한다. 다른 창에서 이미 코드가 바뀌었을 수 있다. 기존 브랜치와 PR을 덮어쓰지 않는다. 테스트 저장소를 단순 이름 변경해 최종 저장소의 이력을 대체하지 않는다.

우선 뜨는 상권의 수치와 디자인을 고정한다. 그 뒤 내상권 분석의 운영자/예비 창업자 모드와 팀원 기능을 별도 회귀 목록으로 이식한다. 젠트리피케이션은 검증 전까지 개발 예정 상태다.
