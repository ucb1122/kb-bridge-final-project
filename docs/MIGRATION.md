# 테스트 프로젝트 이식 순서

참고 자료: C:/dev/03_toy-project/kb-test-project.zip과 테스트 저장소. 압축본에는 node_modules, 캐시, 생성 DB, savepoint도 포함되어 있다. 이런 실행 산출물을 최종 저장소로 복사하지 않는다.

## 제품 기준

목표는 상권 순위 화면 자체가 아니라 지역 신호를 사업자의 경영·금융 판단과 지원·상담 준비에 연결하는 것이다. 상권 데이터의 단위 검증과 동시에 사업자 입력, 현금흐름 시나리오, 비차입 지원 경로의 계약을 별도 작업으로 설계한다. 예비 창업자의 가정값과 현재 사업자의 실제 입력은 구분한다.

## 이슈 #3 이식 상태

- 완료: 테스트 생성 SQLite·공식 순위/매출 스냅샷을 로컬로 복사하는 명령, Python 순위·상세조건·보고서 어댑터, 카카오 지도 구성 요소, 팀원 KB 노랑/흰 카드 테마, 현재·예비 사업자 지역/업종 조회, 반경 내 인허가 관측, 영업점 후보, 간이 월세·가상 신규대출 시나리오, 상담 준비 메모, 뜨는 상권 PDF 5종과 ZIP.
- 별도 구현 필요: 제공된 원본 CSV에서 동일 스냅샷 재생성, 팀원 보행거리·시간·다각형 도구, 개별 지도 레이어·비교담기, 팀원 금융상담 전체 단계와 PDF 5종, 공식 지원 요건 갱신, 미래 젠트리피케이션 모델 검증.
- 현재 실행 자료는 `data/local/`의 테스트 시점 복사본이다. 최신 데이터나 개인별 금융정보로 해석하지 않는다.

## 단계

1. 현재 seoul_data 원본을 목록화하고 source metadata와 해시를 검증한다. 최근 CSV와 연도별 ZIP의 중복을 제거한다.
2. 상권별 점포 수 하나로 원본 → 정규화 → SQLite → 서비스 → Streamlit 화면의 수직 기능을 만든다.
3. 뜨는 상권의 기간·업종·순위와 공식 스냅샷을 재현한다. 공식 값이 없는 조건은 로컬 계산임을 표시한다.
4. 카카오 지도에 동일 지역 코드와 경계를 연결한다. 다른 지도 라이브러리 자산을 무조건 복사하지 않는다.
5. 내 상권 분석의 현재·예비 사업자 모드를 구분하고, 현재 사업자의 임대료 스트레스·간이 현금흐름부터 수직 구현한다. 이후 추가 차입 역효과, 금융 선택지 비용 비교, 공개 지원 요건 확인과 상담 준비 자료를 각각 검증한다. 인허가 개별 업소와 상권 집계의 차이를 유지한다.
6. 공식 지원·상담 링크의 갱신 시점과 상태를 확인하고, 사용자 동의 없는 입력 보관·전달을 금지한다. Ollama 의견은 검증된 보고서 위에 선택적으로 붙이고 fallback을 둔다. PDF 생성은 출처·권리와 출력 검증 후 적용한다.
7. 젠트리피케이션 모델은 노트북의 시점·라벨·군집 안정성·예측 성능을 다시 확인한 후 별도 검증 이슈로 진행한다.

참고 금융 자료는 SafeGuard_AI_금융차별화_5대기능_입문자용_상세설계_v5.pdf, 세이프가드 AI 발표 자료.pdf, KB 상권브릿지 금융상담 플로우.png다. 젠트리피케이션 노트북과 팀원 ZIP·신호등 보고서도 설계 참고 자료다. 이 파일은 현재 런타임 필수 파일이 아니다.

테스트 프로젝트의 알려진 주의점: 분기 추정매출 합계와 점포당 월평균, 유동인구 총량과 ha당 밀도는 다른 지표다. 공식 TOP 10 스냅샷은 일부 기본 조건에만 적용한다. 확인된 공식 보고서 표시값은 일부 지역뿐이다. 2025Q1~2026Q2 등 테스트 당시 범위를 최신 자료의 범위로 가정하지 않는다.
