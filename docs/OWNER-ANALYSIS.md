# 내 상권 분석: 입력값과 계산 범위

팀원 테스트 프로젝트의 `owner-regional-data.json`, 영업 인허가 관측, 업종 카탈로그를 화면에 연결한다. 원본 스냅샷은 2026년 1·2분기 기준이며 새로운 시점의 실시간 값으로 취급하지 않는다.

## 나는 사장

1. 상호 또는 확보된 주소로 영업 인허가 기록을 찾고 점포 좌표를 선택한다. 개인 사업자 인증이나 실제 소유 관계는 확인하지 않는다.
2. 인허가 업태와 300·500·1,000m 반경을 고른다. 주변 건수는 좌표가 있는 인허가 기록의 관측 수이며, 공식 점포수나 경쟁 업소의 실제 영업 여부가 아니다.
3. 점포와 중심 좌표가 가장 가까운 공식 상권을 제안한다. 중심점 근접은 상권 경계 포함 판정이 아니므로 사용자가 상권을 바꿀 수 있다.
4. 공식 점포수와 추정매출은 **선택한 상권 코드와 공식 서비스업종 코드**로 조회한다. 음식 업태 10종은 팀원 코드 대응표로 연결한다. 대응 코드가 없는 업태는 값을 숨겨 전체 업종을 해당 업태의 값처럼 보이지 않게 한다. 인구 지표는 상권 전체 기준이다.
5. 금융 계산은 사용자가 직접 넣은 월매출·비용·월세·상환액과 가정한 대출 조건만 사용한다. 공개 상권 매출을 내 점포 매출로 쓰지 않는다.

## 나도 곧 사장

1. 공식 업종군 또는 세부 업종, 비교 지표, 자치구·행정동을 고른다.
2. 선택한 상권·업종의 현 분기와 전 분기 값이 모두 있고 전 분기 값이 양수인 경우에만 `(현 분기 − 전 분기) / 전 분기 × 100`을 계산한다.
3. 증가율 내림차순, 현 분기 값 내림차순, 상권 코드 오름차순으로 상위 10개 상권을 제시한다. 유동인구·거주인구는 업종과 관계없는 상권 전체 지표이다.
4. 선택한 상권의 공식 집계와 분기 비교를 바로 볼 수 있다. 순위는 입지 추천이나 개인 사업 매출 예측을 뜻하지 않는다.

두 모드는 같은 지도·보고서 폭을 사용하며, 왼쪽 필터는 뜨는 상권의 카드 간격과 버튼 색을 따른다.

## 오른쪽 보고서 항목

- **한눈에 보기:** 선택 업종·공식 상권의 점포수와 제공된 추정매출, 상권 전체 유동인구의 현 분기 값·전분기 차이. 점포 위치가 있으면 별도 반경 인허가 관측, 예비창업자는 선택 지표의 비교 순위를 표시한다.
- **업종·경쟁:** 공식 점포수·개업·폐업, 상권 내 업종별 점포수 상위 10개. 운영 중인 점포를 선택했다면 반경 안 인허가 기록 수와 예시를 별도 표시한다. 허가별 기록을 고유 경쟁 점포수로 간주하지 않는다.
- **매출:** 원본 추정매출 금액, 전분기 비교, 매출 건수와 주중·주말 금액. 매출 제공 업종 수/점포수 제공 업종 수를 병기한다. 원본 금액을 월평균·분기 합계로 임의 변환하지 않는다.
- **고객·인구:** 유동·상주·직장인구의 현 분기, 전분기, 차이. 모두 업종과 관계없는 공식 상권 전체 기준이며 연령·성별·시간대는 자료가 없어 표시하지 않는다.
- **주변 환경:** 공식 상권 유형·행정동 속성·면적·코드. 점포 위치가 있으면 검색 주소와 상권 중심점까지의 직선거리, 반경 관측을 표시한다. 근접 거리는 상권 경계 포함 여부를 뜻하지 않는다.
- **금융상담 준비:** 기존 직접 입력 시나리오 계산을 유지하며 공개 상권 매출을 개인 매출 입력값으로 대입하지 않는다.
