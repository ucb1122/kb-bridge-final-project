# Architecture

## 현재 범위

이 저장소는 상권 변화와 개별 사업자의 경영 부담을 연결하고, 금융·정책 지원 및 상담 준비로 이어 주는 소상공인 의사결정 지원 서비스를 Python·Streamlit·SQLite로 구축할 최종 프로젝트다. 상권 분석은 근거를 제공하는 한 영역이며, 현재 사업자와 예비 창업자의 판단 흐름이 중심이다. 이슈 #1은 실행 가능한 화면 탐색 골격, 설정 계약, 기본 데이터 모델과 협업 규칙을 정한다. 테스트 ZIP의 JavaScript 화면·서버를 그대로 복사하거나 이미 이식했다고 주장하지 않는다.

## 계층과 의존 방향

| 위치 | 책임 |
| --- | --- |
| app.py, app_pages/ | Streamlit 진입점과 뜨는 상권·내상권 분석·젠트리피케이션 경고 화면 |
| kb_bridge/ui/ | 여러 화면이 공유할 표시 도우미. 데이터 계산을 넣지 않음 |
| kb_bridge/services/ | 지역 탐색, 사업자 진단, 금융 시나리오, 지원 정보, 상담 준비, 보고서 사용 사례 조합 |
| kb_bridge/domain/ | 지역 지표·위험 신호, 사업자 입력, 현금흐름·상환 시나리오의 순수 규칙과 계산 |
| kb_bridge/repositories/ | SQLite 연결·쿼리·스키마. Streamlit을 import하지 않음 |
| kb_bridge/ingestion/ | CSV·ZIP·GeoJSON의 출처 확인, 인코딩 처리, 정규화, 중복 검사 |
| kb_bridge/integrations/ | 카카오 지도·서울시 API·Ollama·정책금융 등 외부 연결 |
| assets/ | 권리·출처가 확인된 화면용 아이콘·폰트·이미지 |
| data/, output/ | 원본·가공본·로컬 DB와 생성된 보고서 |

화면 → 서비스 → 도메인/Repository/연동으로 호출한다. 적재기는 원본 → 정규화 → SQLite로 흐른다. 목록·지도·지역 보고서는 한 서비스 응답의 지역 코드, 순위, 기간, 단위와 출처를 공유한다. 사업자 입력과 상담 자료는 별도 모델로 다루며 공개 지역 관측값과 혼합하지 않는다.

Streamlit은 별도 웹 API 서버 없이 Python 서버에서 화면과 업무 코드를 실행한다. 현재의 프론트/백엔드 분리는 실행 프로세스가 아니라 코드 책임의 분리다. 나중에 외부 앱에 API를 제공해야 할 때만 별도 API 서버를 검토한다.

## 화면 경계

- 뜨는 상권: 행정동/상권 구분, 자치구·업종·분기·정렬 조건, 순위·지도·리포트. 공식 응답과 로컬 계산을 구분한다.
- 내상권 분석: 나는 사장과 나도 곧 사장을 같은 메뉴의 두 모드로 둔다. 위치·반경·상권 경계, 업종, 보고서, 금융상담 흐름을 공유하되 현재 운영자와 예비 창업자의 입력은 구분한다.
- 젠트리피케이션 경고: 검증된 지역별 결과 전까지 개발 예정으로 표시한다. 과거 재현 노트북만으로 미래 경고를 단정하지 않는다.

금융 흐름은 지역 위험 신호 → 사업자 상황 확인 → 진단 주제 선택 → 입력값 기반 시나리오 → 은행·정책·보증·경영지원 정보 → 상담 준비 자료 순서다. 로그인과 실제 인증·사업자 자동조회·상담 접수·예약은 아직 구현하지 않았다.

## 경영·금융진단과 상담 경계

| 기능 영역 | 설계할 판단 | 현재 상태 |
| --- | --- | --- |
| 임대료 스트레스 | 실제 인상 요청 여부와 사용자 입력 월세·비용을 확인하고 가정별 월 현금흐름을 비교 | 미구현 |
| 금융 선택지 비교 | 무대응·신규 차입·대환/조건변경의 월 부담과 총비용을 상환방식별로 비교 | 미구현 |
| 추가 차입 역효과 점검 | 지속 적자·연체 우려·차입 목적을 질문하고 비차입 지원도 제시 | 미구현 |
| 지원 공백 확인 | 공식 공개 요건과 입력값을 대조하고 일치·불일치·미확인을 구분 | 미구현 |
| 임대인·임차인 상생금융 | 임대료 동결/인하와 가상 금리우대의 효과를 연구용으로 비교 | 향후 제안; 현재 판매 상품 아님 |
| 상담 준비 | 동의한 입력과 진단 요약·질문 목록을 정리하고 공식 상담 경로를 안내 | 미구현 |

상권 위험도는 개별 사업자의 신용점수·대출 적격성·폐업 확률이 아니다. 사용자 입력은 지역 관측값과 별도로 취급하고 저장·전달 여부, 보존기간, 동의를 먼저 결정한다. 시나리오 금리와 임대료 변화는 가정값으로 표시한다. 공개 요건 비교는 실제 은행 심사나 상품 추천 확정이 아니다. 상담 화면은 접수·예약이 실제 연동되기 전까지 연결 완료로 표시하지 않는다.

## 카카오 지도와 Ollama

- KAKAO_MAP_JAVASCRIPT_KEY는 지도 JavaScript SDK용이다. 지도 렌더링 시 브라우저에 전달되는 키이므로 허용 도메인 설정을 확인한다.
- KAKAO_REST_API_KEY는 향후 서버 측 REST API용이며 브라우저에 전달하지 않는다. 키가 없으면 연동 기능은 명확한 안내를 표시해야 한다.
- OLLAMA_BASE_URL과 OLLAMA_MODEL은 로컬 종합의견 생성 연동의 설정이다. 향후 AI 어댑터가 수치·기간·단위·출처를 담은 검증된 보고서만 입력받고, 연결 실패 시 수치 기반 요약으로 복구한다. AI 문장은 검증된 데이터 자체가 아니다.
- 지도 경계, 마커, 목록, 리포트는 동일 지역 코드와 좌표계 계약을 사용한다. 3D 표현은 실제 건물 높이나 위험도 측정값과 혼동되지 않게 표시한다.

## 이식과 운영 기준

테스트 ZIP에는 Node API, 데이터 수집·적재 스크립트, 카카오 지도, Ollama fallback, PDF 출력과 팀원 화면이 있다. 각 기능은 출처·라이선스·기준 시점·테스트를 확인한 뒤 Python 계층으로 단계별 이식한다. 특히 공식 화면 표시값과 CSV 계산값, 상권·행정동·개별 업소, 월·분기를 혼합하지 않는다.

DB 스키마는 출처를 보존하는 최소 계약이다. 실제 업종·공간 경계·상담 입력·모델 결과 테이블은 첫 수직 기능을 검증하며 결정한다. 스키마 변경은 버전별 마이그레이션으로 관리할 예정이다. 자세한 계약은 DATA-MODEL.md, 순서는 MIGRATION.md를 본다.
