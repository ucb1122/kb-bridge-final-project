# 협업 규칙

제공된 CONVENTION.md와 최종 프로젝트 대화에서 합의한 운영 원칙을 반영한다.

1. 작업 전에 이슈를 만든다. 제목은 [chore] 설명처럼 유형을 붙이고 담당자와 라벨을 지정한다.
2. 최신 develop에서 소문자 feature/<이슈번호>-<domain> 브랜치를 만든다. develop에서 직접 기능 개발하지 않는다.
3. 기능 단위로 작업하고, 구조 결정과 데이터 계약의 근거를 docs/에 기록한다.
4. 관련 검증을 통과하고 diff를 확인한 뒤 [prefix] #<이슈번호> 설명 형식으로 커밋한다.
5. 원격 develop 변경을 확인하고 feature 브랜치에서 충돌을 해결한 뒤 push, feature → develop PR을 연다.
6. 작성자 외 팀원 한 명 이상의 리뷰·승인을 받고 병합한다. 종료된 이슈·PR의 라벨과 마일스톤을 관리한다.

팀원의 예외적인 1회를 제외하면 사용자가 맡긴 Codex가 이슈 생성과 커밋을 처리한다. README 변경은 해당 이슈의 범위와 사용자 요청을 확인한 뒤 리뷰한다.

PR에는 변경 경로, 실행·검증 결과, 자료 출처와 남은 한계를 적는다. 리뷰에서는 지표 단위, 데이터 출처, 비밀키, 자산 권리와 미구현 기능의 표시를 확인한다.
